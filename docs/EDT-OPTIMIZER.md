# EdgeTunnel 实测优选

## 使用

1. 先部署自己的 Pages/Worker VLESS-over-WebSocket 端点。在边缘模块保存域名、UUID 和路径；UUID 必须与端点一致。控制台不会代为创建 Cloudflare Worker，也不会把服务器域名自动当作边缘端点。
2. 候选可手动导入（最多 24 个 IPv4），或填写可信 HTTPS 文本列表（最多 3 个）。每次检测也会从 Cloudflare 官方 IPv4 网段中随机采样；候选限制在官方公网段，拒绝内网和云元数据地址。官方网段来源：https://www.cloudflare.com/ips-v4/ 。采样只是提供候选，不保证地址支持代理。
3. 保存后点击刷新，后台以最多 4 个并发、每候选 2 次检测测量。每次先验证边缘 TLS，再用实际 UUID 发送 VLESS TCP 请求，经隧道验证 `speed.cloudflare.com` 的 TLS，并下载 64 KiB 数据。两个端点都配置时，必须全部成功，排名取较差的延迟和速度。
4. 两次完整连接全部成功的候选才进入优选池。先按延迟与抖动排序，再比较短下载速度；旧首选仍在最佳分数的 15% 范围内时保持首选，减少抖动。全部失败保留原池，并在最后一次成功测量后 6 小时内继续下发上一批实测通过的地址；页面同时显示本轮失败。64 KiB 测量反映短下载表现，不是线路极限带宽；两次采样也不代表长期稳定性。
5. 自动检测仅在 EdgeTunnel 开启时运行，间隔可设 15 分钟至 24 小时，默认 1 小时。后台每分钟检查一次，失败也按间隔重试。刷新只更新配置中的优选池，不修改 x-ui，不换 VPS IP，不修改 DNS。通过代理下载会使用自己的 EdgeTunnel 流量。
6. 客户端需手动/定时更新订阅。结果超过 6 小时或端点配置变更后，不再以该结果生成“实测优选”订阅节点；原池仍保存在配置以便恢复，不会删改原生 VPS 节点。

刷新接口兼容说明：`POST /api/edt/refresh-clean-ips` 返回 `status=started/running`、任务进度 `optimizer`，以及当前保存的 `clean_ips` 快照。快照不是新一轮测速完成的标志；完成状态与实测时间从 `/api/edt/optimizer` 读取。域名填写带有协议或路径时，会先规范化，再校验。

回归覆盖：新增 18 个无真实测速流量的测试，覆盖候选限制、代理路径、完整 VLESS/HTTPS 测量封装、两轮与多端点成功条件、域名兼容、任务调度、令牌权限、重放与过期拒绝、撤销、失败回退、订阅实测标签与有效期。原有刷新测试模拟任务调度，避免测试期间启动真实网络探测。

## 三网探测设备

服务器侧结果仅更新 Anycast/服务器侧池。真实电信、联通、移动结果需要设备实际连接相应运营商网络。线路与地区由管理员登记，并非自动认证的全国代表性结果。不同地区应登记不同设备。设备是信任边界：拥有探测凭据的人可以提交该设备的测速结果。

在页面选择运营商、填写地区，点击登记探测设备。保存只显示一次的专用令牌；如丢失，撤销旧设备后重建。设备只能领取带有端点 UUID 的检测任务和提交本设备结果，不能管理系统。请只登记可信设备。撤销后不能再领取或提交任务；配置中仅保存令牌哈希。

在对应线路的 Linux/小主机/电脑上下载本仓库、创建 Python 3.10+ 虚拟环境，使用项目 hash 锁定依赖，再运行：

```bash
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.txt
read -rsp '探测凭据: ' VPSENTINEL_PROBE_TOKEN
export VPSENTINEL_PROBE_TOKEN
.venv/bin/python scripts/edt_probe.py --server https://你的控制台域名:20540
```

程序每小时领取一次任务、执行与服务器相同的完整测量并上报。`--once` 执行一轮后退出。保持程序运行才有周期结果；可自行通过系统服务运行，令牌置于受保护的环境文件。协调端必须使用有效 HTTPS 证书。

每个任务有效 1 小时，完整结果只能提交一次；候选、结果数、数值范围和端点版本都校验。最多 12 个设备。结果保留 6 小时；同一运营商的多设备结果按候选聚合，失败不会被另一个设备的成功掩盖。没有对应线路的实测结果时，不会把服务器结果标为三网优选。

## 范围

支持 IPv4、标准 VLESS TCP-over-WebSocket、TLS 443 和标准二进制 VLESS 响应。沿用订阅配置中的 `proxy_ip` 路径覆盖（公网 IP 或域名）。不支持非标准握手/私有 CA/客户端证书等扩展。端点部署、三网设备的接入与不同客户端的实际使用需对应环境验收。候选来源失效不阻止手动候选和官方网段采样。

## 合并公开候选池

支持纯 IPv4 和 `IP:443#备注` 文本，忽略宣传行、非 443 端口、IPv6 和非 Cloudflare 公网地址。公开来源使用浏览器 User-Agent 获取，继续验证 HTTPS 证书、禁止重定向及内网访问；每源上限 16 KiB / 256 条，最多三个来源。

已读取可作为候选的列表：

- https://bestcf.pages.dev/wetest/ipv4.txt
- https://bestcf.pages.dev/uouin/all.txt
- https://bestcf.pages.dev/vvhan/ipv4.txt

来源成功结果缓存 30 分钟，获取失败时最多沿用 6 小时内的缓存；状态接口显示来源错误和缓存回退。各来源在运营商分类中交错排列，每轮从手动地址、原池、三网分类、未分类地址和官方网段采样中轮流选取最多 24 个。每类游标持久化，后续轮次继续覆盖候选池。来源标签不作为三网实测证明；候选仅经过完整端点验证后才下发。

## 下载验证目标与误判

原 Cloudflare 下载目标保留兼容。部分端点能代理普通站点，但访问 Cloudflare 自身站点会失败；该结果不能据此判定所有代理请求都不可用。可在页面选择 Wikimedia：通过 `upload.wikimedia.org` 的 HTTPS 范围请求获取指定文件的前 64 KiB，必须返回 206、正确的 Content-Range 和完整数据。不会下载完整 14 MB 文件。文件来源：https://commons.wikimedia.org/wiki/File:Fronalpstock_big.jpg 。

两个目标均验证目标站点 TLS；结果仅证明该验证目标上的代理下载能力，不保证所有网站都能访问。更换验证目标会改变实测指纹，旧结果须重新检测。三网探测设备须使用同版本程序，以支持新的验证目标。
